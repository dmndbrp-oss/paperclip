## Key Finding

Same truncation mismatch as doc-coauthoring: the docx skill is 20,084 chars (50% visible in 10k window). The model added a valid, additive Safety Notes section (correct content, no regressions) but the gate can't credit it because additions land outside the evaluate window.

**R2 token limit:** Setting `num_predict: 3000` was too low for a 10k-verbatim-copy + additions. The model needs ≥ 14,000 tokens to copy the original 10k chars verbatim and then add new content. The workflow's default `num_predict` (unconstrained) is required for correct operation on long skills.

## Recommendation

Both Phase 1 pilot skills exceeded the 10k truncation limit. For Phase 2 fleet rollout on skills > 10k chars, the workflow needs diff-based evaluation or a higher truncation limit. Skills < 10k chars (e.g., smaller utility skills) should be prioritized for Phase 2 to validate the gate accept path.
